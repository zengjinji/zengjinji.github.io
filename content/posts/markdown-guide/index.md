这是一篇**排版示例**。可以把它当作写作时的参考，也可以打开对应的源文件，直接看看语法。

## 用标题组织内容

文章标题写在 front matter 中，正文从二级标题 `##` 开始。把每一节控制在一个主题内，读者就能通过右侧目录快速定位。

### 强调与链接

使用 **粗体** 标记重点，用 *斜体* 补充语气。命令、文件名和变量可以写成行内代码，例如 `hugo.toml`。

链接示例：[Hugo 官方文档](https://gohugo.io/documentation/)。

## 把代码放进代码块

在代码块开头标记语言，页面会自动高亮：

```bash
# 构建用于发布的静态网页
./scripts/hugo.sh --gc --minify
```

也可以展示配置文件：

```toml
baseURL = 'https://zengjinji.github.io/'
locale = 'zh-CN'
title = 'zengjinji · 技术手记'
```

如果要展示终端输出，可以使用 `text` 代码块，让命令和结果保持清晰。

## 用列表表达步骤

有先后顺序的操作适合用编号：

1. 说明问题背景。
2. 给出最小可复现的例子。
3. 记录解决方式。
4. 写下验证结果。

并列的注意事项适合用项目符号：

- 一段只讨论一个核心问题。
- 示例代码尽量短小。
- 给出必要的版本和环境信息。

## 表格适合做比较

| 内容 | 放在哪里 | 用途 |
| --- | --- | --- |
| 文章 | `content/posts/` | Markdown 正文与文章信息 |
| 站点配置 | `hugo.toml` | 标题、网址与语言 |
| 页面模板 | `layouts/` | 首页、文章页与标签页 |
| 静态资源 | `static/` | 图片、样式与图标 |

## 引用与图片

> 把复杂的事情讲清楚，往往要从一个具体的例子开始。

文章图片可以放到与 `index.md` 相同的目录，然后通过 `![图片说明](example.png)` 引用。图片说明应描述图片内容，方便读者和辅助阅读工具理解。

这个示例没有放置额外图片；你可以按自己的内容加入。
